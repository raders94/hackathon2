# PORTCAST 업로드 체크리스트 (GitHub + Streamlit Community Cloud)

## 0. 파일 확인

- [ ] ZIP 압축을 풀면 `app.py`, `requirements.txt`, `packages.txt`가 최상위에 있다.
- [ ] `.streamlit/config.toml`, `src/logic.py`, `src/explainability.py`가 존재한다.
- [ ] `assets/throughput_nonGT_2020_2024.cbm`, `assets/modelb_weather_residual_effects.csv`, `assets/learning_annual_slopes.csv`가 존재한다.
- [ ] `assets/`에 원본 선박 단위 이력 및 실시간 API 키/계정정보가 없다.
- [ ] 원천자료·모델의 외부 업로드 및 재배포 사용권을 확인했다. 미확인 시 공개 배포를 보류한다.

## 1. GitHub 업로드

1. https://github.com/new 접속 → 빈 저장소 생성. 원본 사용권을 확인하기 전에는 공개 저장소를 만들지 않는다.
2. `Add file` → `Upload files`를 열어 압축 해제한 **모든 파일과 폴더를 업로드**. ZIP 파일만 올리는 것은 안 된다.
3. 반드시 저장소 루트에 `app.py`가 보이는지 확인한다. Windows에서 숨김 폴더 `.streamlit`이 함께 들어갔는지 확인한다.
4. `Commit changes`로 저장한다.

## 2. Streamlit Community Cloud 게시

1. https://share.streamlit.io 에서 GitHub를 연결한다.
2. `Create app` → 저장소·브랜치 `main`을 선택한다.
3. `Main file path`를 `app.py`로 입력한다.
4. `Advanced settings`에서 Python **3.12**를 선택하고 저장한다.
5. Deploy 이후 로그에서 설치 오류를 확인하고 본문 6개 탭의 표시를 확인한다.

## 3. 배포 후 수동 검증

- [ ] 01 탭: BCT / 2027-11-20 10:00 / 풍속 6m/s / 파고 1.2m / 시정 5000m / 혼잡 상, 2척 가정에서 합산 예상 약 **58.58 작업단위/h**가 나타난다. 기본 작업량은 396으로 설정한다.
- [ ] 01 탭: SHAP 기준값+기여도 합이 모델 예측과 일치한다.
- [ ] 02 탭: 7개 터미널 비교, P90/P95 근거 차트가 표시된다.
- [ ] 03 탭: BCT 모델 B 강풍 4~6회 −10.74%, 개선 추세 p=0.794 및 비교군 p=0.910이 표시된다.
- [ ] 04 탭: 디지털 트윈은 **개념 실험실 / 사용자 가정 목표**로 표시된다.
- [ ] 05 탭: 90일 실증 및 검증한계 문구가 표시된다.
- [ ] 06 탭: 2025 악천후 조건별 검증 표가 표시된다.
- [ ] 브라우저에서 한국어와 그래프가 깨지지 않는다. `packages.txt`의 `fonts-nanum`은 Seaborn 한국어 폰트용이다.

## 문제가 생기면

- `ModuleNotFoundError` → `requirements.txt` 설치 로그 점검
- `FileNotFoundError` → 저장소 루트에서 `assets/`와 `.streamlit/` 상대 경로 점검
- `Model file error` → CatBoost 모델 `.cbm` 2개가 실제로 올라갔는지 확인
- `Not enough resources` → 앱 리소스의 제한·동시 접속 수 점검
- `Permission` → 소스·학습모형 이용허락 확인 후 배포 범위 제한

최종 주의: 이 ZIP은 배포 준비 파일이며 GitHub 저장소에 실제로 게시하거나 배포 URL을 만든 상태가 아닙니다.
